# 校园智脑 — 智能体化升级说明（参赛版 v3.1）

> 对应参赛规划：开放赛题一「生成式大语言模型与智能体」
> 目标：把单次 RAG 升级为「感知-规划-检索-评估-行动」多任务智能体，同时支持个性化、记忆、数据分析、热点话题、内容安全审核、情绪预判与**主动式澄清引导**，并采用**场景配置中心**实现模块化可拼接。

---

## 一、新增模块

| 文件 | 作用 |
|------|------|
| `agent.py` | **CampusAgent 智能体总控**：意图路由 → 查询规划 → 双通道检索 → 相关性评估 → 查询改写 → 个性化生成 → 自查修复 → 主动引导 → 行动输出（含完整推理轨迹 trace、证据溯源 evidence、情绪预判 emotion） |
| `emotion.py` | **EmotionPredictor 情绪与意图预判**：零成本规则（词典+正则）识别情感极性/情绪标签/意图类别/紧急度，可选 LLM 增强 |
| `clarify.py` | **ClarifyGuide 主动式澄清与引导**：把客服从"被动回答"升级为"主动引导"——主动识别信息缺口 → 选项式追问 → 回答后延伸话题 → 紧急行动指引 |
| `scene_config.py` | **场景配置中心（模块化核心）**：情感/意图词典、引导话术、行动指引全部集中于此，**换场景只需改这一个文件**，引擎零改动复用 |
| `moderation.py` | **ModeratorAgent 内容安全审核智能体**：规则引擎 + LLM 复核两级检测（广告/辱骂/色情/诈骗/隐私），输出风险等级与处理建议；支持单条审核与批量巡检 |
| `analytics.py` | **AnalyticsAgent 数据分析智能体**：聚合论坛统计 → LLM 生成数据洞察报告 |
| `hot_topic.py` | **HotTopicAgent 热点话题识别**：主题词聚类 → 热点榜单 + 板块热度（供前端展示） |
| `memory.py` | **记忆模块**：会话内多轮记忆 + 用户点赞/点踩反馈记忆（驱动个性化） |
| `mock_forum.py` | **Mock 论坛后端**：内置 20 条典型校园帖，独立于真实论坛运行，保证可复现演示 |
| `eval_benchmark.py` | 评测脚本：度量回答率 / 平均耗时 / LLM 调用成本；**`--compare` 对照实验量化创新点** |

## 二、原有模块改动

| 文件 | 改动 |
|------|------|
| `generator.py` | 双 LLM 后端（`ollama` 本地 / `api` 云端，OpenAI 兼容，可一键切换）；`_chat_ollama`/`_chat_api`；`generate_personalized()`（画像注入）；`score_relevance()`（相关性评分） |
| `config.py` | 新增 LLM 后端、智能体循环、双通道检索、自查修复、用户画像、记忆、热点等全部可配置项 |
| `bot.py` | 挂载 `agent`/`analytics`/`hot_topic`/`memory`/`moderator`；新增 `/ask/agent`、`/ask/analytics`、`/hot`、`/feedback`、`/moderation`、`/moderation/scan`、`/trace` 端点；API 模式内置前端展示面板（`/`） |
| `embedding.py` | 双通道之一：ChromaDB 稠密检索（Ollama nomic-embed-text，768 维） |
| `__init__.py` | 导出 `CampusAgent`、`PersonaProvider`、`AnalyticsAgent`、`HotTopicAgent`、`ModeratorAgent` 等 |

## 三、智能体工作流

```
用户问题 (可选 userId=个性化 / sessionId=会话记忆)
   │
   ├─[0] 情绪与意图预判（零成本规则）→ 情感极性 / 意图类别 / 紧急度
   │
   ├─[0.5] 缓存命中? → 直接返回历史答案（零成本、毫秒级）
   │
   ├─[1] 意图路由 (LLM+规则多级) → 是否提问 / 核心意图
   │
   ├─[2] Planner 查询规划 (LLM)
   │     → 意图 + 子查询分解 + 关键词提取
   │
   ├─[3] Retriever 双通道检索 + RRF 融合（最多 AGENT_MAX_ROUNDS 轮）
   │     ├─ 通道A 稠密: 问题 → nomic-embed-text → ChromaDB Top-K
   │     ├─ 通道B 稀疏: BM25(Tfidf) Top-K
   │     ├─ RRF 结果融合排序
   │     └─ 相关性评估 → 达标收敛 / 不足则改写查询再检索
   │
   ├─[3.5] 主动式澄清与引导（信息缺口 → 选项式追问，引导用户补充）
   │
   ├─[4] Persona 用户画像构建
   │     → 用户资料 + 收藏标题(兴趣) + 发帖主题(行为) + 历史反馈记忆
   │
   ├─[5] Generator 个性化生成（注入检索证据 + 画像 + 会话记忆 + 情绪风格）
   │
   ├─[6] Critic 自查修复（生成后审查）
   │     → 检查偏离问题/缺细节/幻觉 → 不达标则注入反馈重新生成
   │
   ├─[6.5] 回答后主动引导（延伸话题 + 紧急行动指引，形成对话闭环）
   │
   └─[7] 行动输出：结构化回复 + 推理轨迹 trace + 证据溯源 evidence + 情绪预判（前端可视化）
```

## 四、模块化与场景化改造指南（核心亮点）

> 本项目以**引擎与场景解耦**为设计原则，可方便地拼接/改造为其他场景的智能客服系统。

### 4.1 模块划分（职责单一、接口清晰）

| 模块 | 输入 | 输出 | 是否依赖业务词 |
|------|------|------|----------------|
| `emotion.py` 情绪预判 | 用户文本 | 情感/意图/紧急度 | ❌（词典来自 scene_config） |
| `clarify.py` 主动引导 | 用户文本+预判 | 引导追问/延伸话题 | ❌（话术来自 scene_config） |
| `agent.py` 总控编排 | 查询 | 回答+轨迹+证据 | ❌ |
| `moderation.py` 内容审核 | 文本 | 风险等级/建议 | ⚠️（规则可配） |
| `analytics.py` 数据分析 | 聚合数据 | 洞察报告 | ❌ |
| `hot_topic.py` 热点识别 | 帖子 | 热点榜单 | ❌ |
| `mock_forum.py` 数据源 | - | 模拟数据 | 场景数据（可替换） |

### 4.2 拼接一个新场景只需两步

1. **改 `scene_config.py`**：替换情感/意图词典、引导话术、行动指引（纯文本，无需懂代码）。
2. **换数据源**：把 `mock_forum.py` 或 `RAGSystem` 指向新场景的数据（API 或本地库）。

引擎代码（emotion / clarify / agent / generator）**零改动**即可复用全部智能体能力。

### 4.3 示例：拼接成"电商售后客服"

仅需在 `scene_config.py` 中调整：
```python
SCENE_NAME = "电商客服"
INTENT_DICT = [("退换货", ["退货","换货","退款"]), ("物流", ["快递","发货","物流"]), ("售后", ["保修","维修","客服"])]
URGENT_ACTION = {"退换货": "请先与店铺客服确认是否符合七天无理由退换条件"}
```
→ 其余情感感知、主动引导、紧急升级等能力原样生效。

## 五、API 端点

| 端点 | 说明 |
|------|------|
| `POST /api/bot/ask/agent` | 智能体入口 `{"query":"...", "userId":可选, "sessionId":可选}`，返回含 `evidence` 证据溯源 |
| `POST /api/bot/ask/analytics` | 数据分析入口 `{"query":"请分析论坛趋势"}` |
| `POST /api/bot/ask/async` | 异步智能体入口（aiohttp） |
| `POST /api/bot/trace` | 智能体 + 返回推理轨迹（可解释性演示） |
| `GET  /api/bot/hot` | 热点话题榜单（前端展示） |
| `POST /api/bot/feedback` | 用户反馈（点赞/点踩）记录，驱动个性化 |
| `POST /api/bot/moderation` | 单条文本内容安全审核 `{"text":"..."}` |
| `GET  /api/bot/moderation/scan` | 论坛帖子批量内容安全巡检（健康度报告） |
| `GET  /` | 前端展示面板（ECharts + 对话 + 推理轨迹 + 证据来源 + 审核演示） |

## 六、评测脚本

```bash
python eval_benchmark.py            # 直接调用智能体评测（内置10个校园问题）
python eval_benchmark.py --api      # 通过已启动的 Flask 服务评测
python eval_benchmark.py --compare  # 对照实验：量化双通道/自查的贡献
```

输出指标：`answer_rate`（近似质量）、`avg_llm_calls`（成本）、`avg_time_ms`（耗时）。
`--compare` 模式对比「完整版 / 仅向量检索 / 关闭自查」三档配置，产出可写入文档的量化对比表。

## 七、一键演示（推荐）

**方式A：一键脚本（Windows）**——双击 `start_all.bat`，自动检测环境、装依赖、启动 Mock 论坛 + 智能体服务并打开演示面板。

**方式B：手动启动**

```bash
# 第1步：启动 Ollama（需已安装）
ollama serve

# 第2步：启动 Mock 论坛后端（端口 4477）
python mock_forum.py

# 第3步：启动智能体 API 服务 + 前端面板
python bot.py api            # http://localhost:5000 打开演示面板

# 第4步：重建向量索引（首次运行）
python bot.py index
```

**自动化录屏演示**：`python record_demo.py` 可自动操作前端并录制约3分钟的演示视频底片（情绪预判→智能问答+SSE轨迹→内容安全审核→巡检→数据分析），详见《项目视频录制指引》。

## 八、关键配置项（config.py）

| 配置 | 默认 | 说明 |
|------|------|------|
| `LLM_BACKEND` | `ollama` | `ollama` 本地零成本 / `api` 云端 OpenAI 兼容 |
| `LLM_OLLAMA_MODEL` | `deepseek-r1:1.5b` | 本地推理模型 |
| `EMBEDDING_BACKEND` | `ollama` | 向量化模型后端 |
| `EMBEDDING_MODEL` | `nomic-embed-text` | 本地向量化模型 |
| `AGENT_MAX_ROUNDS` | 3 | 检索-评估循环最大轮数 |
| `AGENT_SCORE_THRESHOLD` | 0.65 | 相关性收敛阈值 |
| `AGENT_DUAL_RETRIEVAL` | true | 双通道检索（向量+BM25） |
| `AGENT_SELF_CRITIQUE` | true | 生成后自查-修复闭环 |
| `AGENT_QUERY_REWRITE` | true | 是否启用查询改写 |
| `AGENT_EXPLAIN` | true | 是否输出推理轨迹 |
| `EMOTION_USE_LLM` | false | 情绪预判是否启用 LLM 增强（默认纯规则零成本） |
| `CLARIFY_USE_LLM` | false | 主动引导是否启用 LLM 生成追问（默认规则零成本） |
| `PERSONA_ENABLED` | true | 是否启用个性化 |
| `MEMORY_ENABLED` | true | 会话 + 反馈记忆 |
| `ANALYTICS_TOP_K` | 10 | 统计 Top-K |

> 以上均为增量改造，不破坏原 `bot.py api / scan / index` 模式与原有 `/api/bot/ask` 端点。全链路 Ollama 本地运行，零 API 成本，隐私数据不出本地。
> 场景资源统一在 `scene_config.py` 中配置，换场景仅需修改该文件，详见第四节。
